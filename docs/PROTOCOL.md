# IINE L1241 私有 BLE 适配

[返回首页](../README.md)

## 识别边界

已测 L1241 在“配对 + A”及“配对 + Y”测试中都暴露名为 `IINE GAMEPAD` 的 BLE 配置接口，未找到标准 HID `0x1812`。公开固件推荐实测成功的 **配对 + A，约 3 秒**路径。

本实现通过私有配置接口开启临时输入测试页；不要求 C3 支持经典蓝牙。不能从这些结果推断手柄所有游戏模式或所有 IINE 型号的传输方式。

| 服务 UUID | 特征 | 用途 |
| --- | --- | --- |
| `d7f010e0-660d-46e9-96c3-19c4148bdab5` | `d7f010e1` / `d7f010e2`（相同基 UUID） | Write / Notify；本项目使用 |
| `0xff12` | `ff13` / `ff14` / `ff15` | 发现过的升级侧接口；不访问 |

身份应答长度必须为 8 字节，前 6 字节匹配 `07 10 02 20 27 02` 才启用 L1241 输入映射。完整实测记录为 `07 10 02 20 27 02 09 51`。其他身份保留原始数据诊断。

## 握手与维持

```text
订阅 e2 通知
  → 0x91 身份查询（检查回复序号、格式、CRC）
  → 0xB0 / 00 01 能力查询
  → 0x1D / 02 DF AB 进入测试模式
  → 约 500 ms 后 0x1D / 05 DF AB 00 06 05 打开按键测试页
  → 每 1 秒维持测试页
  → 接收 0x1F 输入事件
  → 用户断开时尝试 0x1E / 02 DF AB 返回普通模式
```

只进入基础测试模式时，实测仅短暂收到数据；测试页及定时维持让输入持续更新。链路超时、查询重试和异步断开均在 NimBLE host task 中管理。

请求有显式白名单；不发送固件升级、恢复出厂、按键映射、宏、校准或灯效写入。身份 / 能力查询应答使用 `0x19` 和请求序号匹配。`0x90` 名称查询在白名单中，但当前握手不发送它。

## 帧与输入记录

单帧最多 20 字节，payload 最多 15 字节。帧包含 opcode、长度、序号、nonce、payload 和 CRC8（反射多项式 `0xEB`），并按协议进行混淆。实现见 [`iine_protocol.c`](../main/iine_protocol.c)。去重针对解码后的输入内容，不把序号、nonce 或 CRC 变化当成操作。

`0x1F` 的解码 payload：首字节为剩余数据长度，后接一条或多条**增量记录**。每条先给状态 `0/1`，再给键码；未出现的控件保留旧状态。整包校验完成后才提交状态，未知记录或截断不会部分修改状态。

| 操作 | 十六进制键码 | 记录总长度 |
| --- | --- | --- |
| A / B / X / Y | `01 / 02 / 03 / 04` | 2 字节 |
| L / R | `05 / 06` | 2 字节 |
| ZL / ZR | `07 / 08` | 4 字节：状态、键码、轴值、附加字节 |
| − / ＋ | `5D / 5E` | 2 字节 |
| L3 / R3 | `0B / 0C` | 2 字节 |
| 下 / 上 / 右 / 左 | `0D / 0E / 0F / 10` | 2 字节 |
| 左 / 右摇杆 | `12 / 13` | 6 字节：状态、键码、处理后 X/Y、原始 X/Y |

摇杆处理值范围 0–255，中心 128，向右 / 向下递增；显示使用处理后坐标，不另加死区。ZL/ZR 在已测设备中为 0 / 255，不据此声称支持模拟扳机。

```text
02 01 01             A 按下
02 00 01             A 松开
04 00 01 00 02       A、B 同时松开
04 01 07 FF 00       ZL 按下
06 01 12 00 7B 00 7B 左摇杆向左
```

统一状态中，12 个按钮依次为 A、B、X、Y、L、R、ZL、ZR、−、＋、L3、R3；轴顺序为左 X、左 Y、ZL、右 X、右 Y、ZR。十字键 bit 0/1/2/3 分别为上/下/右/左。

## 数据与参考

[`tests/fixtures/l1241_fw2702_input.txt`](../tests/fixtures/l1241_fw2702_input.txt) 包含 358 条实机解帧后 payload，不包含设备地址或周边蓝牙日志。测试检查 12 按键及释放、十字键、六路轴的 0/255 端点和组合事件。

传输格式研究参考 [x20ctl 的 KeyLinker 协议调查](https://github.com/AmjadAAYD/x20ctl/blob/553ad76f89d19706a1bd0e45d8aab6f2c14ed231/docs/01-protocol.md)。本项目独立实现有界 C 编解码器，L1241 控件布局来自逐键实测；未引入 x20ctl Python 库。该仓库研究的其他型号不能视为本项目已验证型号。
